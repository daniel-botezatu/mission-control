# Developer memory refactor — implementation decisions

Decision date: 2026-10-21. This supersedes the previous built-in AI and external-ingestion design.

The inspected application has a Rust/Tauri desktop shell, a portable C# collector/SQLite core, and an existing C# stdio MCP executable. Retain those working boundaries and the same data directory. Rewriting the tested SQLite recovery pipeline in Rust would duplicate implementation without a demonstrated resource benefit. Rust continues to own desktop lifecycle; the backend owns local indexing; the independently launched MCP process opens the database read-only.

Mission Control exposes five progressively retrieved history tools. It contains no model clients, reasoning prompts, agent loop, GitHub/Slack collectors or their background workers. Claude Code and Codex supply reasoning and connect separately to the official external MCP servers. At the user's subsequent request, desktop 0.4.1 adds a small read-only authored-PR card through the user's existing official GitHub CLI account. This desktop-only query does not enter the memory database or MCP and creates no background polling or token configuration. Host-specific packages share workflow instructions but use each host's actual configuration format. External read permissions must be restricted by provider settings and host tool allowlists; a skill alone is not a security boundary.

Discovery identifies candidate local projects, including multi-repository workspaces such as SP. Discovery never grants permission. All projects start unapproved on upgrade. Indexing and every read enforce an explicit approved filesystem/repository boundary; project labels and user corrections cannot authorize another folder. Unknown projects remain excluded. Approval resets recoverable stream positions for bounded catch-up. Revocation removes indexed content and dependent local/search data.

Migration takes a SQLite-consistent backup before changing the existing schema. Relevant historical conversations and local preferences remain available for approval and re-extraction; old external content, derived AI state, and obsolete schema are removed. The original refactor queued old credential references for cleanup. That runtime adapter and its UI were removed in 0.4.18 after retirement; historical migration metadata remains for schema compatibility. The desktop no longer accesses OS credential stores or transfers credentials into host configuration. Backups remain sensitive local archives and are documented separately from the live index.

Index only genuine human messages and reliably identified final assistant responses, with stable session/turn/exchange identities and original references. Do not turn intermediate assistant text, reasoning, tool logs, or an assistant's completion claim into verified outcomes. Unsupported formats and unavailable/expired originals produce coverage gaps. WSL uses an in-environment collection path where demonstrated; cross-boundary live-watching is not assumed reliable.

Validation covers allowlist ingestion/retrieval, stale read handles after revocation, parser boundaries, partial writes and restart, MCP protocol calls and host configuration discovery, safe config installation/removal, UI without any AI service, and a fresh five-minute quiet process-tree measurement. Account-specific OAuth and any unavailable operating-system or host behavior are reported as unverified rather than simulated success.

Current official sources and reference-project findings are retained in the research appendices produced with this refactor. Root research, setup, migration, and benchmark documentation will be rewritten around the delivered behavior.
