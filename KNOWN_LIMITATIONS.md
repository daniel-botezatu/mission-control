# Known limitations

Source 0.4.11 adds portable setup, complete Mac sidecar/resources packaging and configurable paths. Windows checks pass; actual Mac execution and signed/notarized distribution remain unverified. See [the team-readiness audit](docs/team-readiness-audit.md). These changes do not resolve the recap-quality and direct-Slack limitations below.

Installation note, October 25: **0.4.10 is now installed at the user's request**, following disclosure of the failed recap-quality comparison. Desktop remains 0.4.8. The October 23 hold described below records the earlier evaluation decision; its coverage gaps remain unresolved.

- Memory plugin 0.4.9 exposes complete date-bounded user/final message delivery, not automatic semantic topic summaries. The calling host must read the stream, group subjects and reconcile later evidence. Protocol and synthetic scenario tests do not prove that every future model follows the workflow; oversized days may still require an explicit partial-coverage answer.
- Outline reads are removed from recaps; the legacy API remains compatible. Claude can split larger windows among fresh history-only readers, but merging ledgers is still lossy and receipts prove delivery, not perfect recall. Smaller windows use one reader because measured helper overhead can increase billed cost. No fixed token/cost reduction is claimed. Codex retains the full-read fallback; parallel capability alone does not provide a verified per-child tool allowlist. The main Claude coordinator retains normal host permissions; only its children have enforced history-only tools.
- Slack response filtering is deferred at the user's request: direct Slack tool responses can contain secrets and can be stored in host transcripts. Local-history redaction does not intercept them.
- The Windows GitHub launcher reuses the existing GitHub CLI credential in child-process memory with a pinned official server and fixed read-only tool set. It does not persist a credential itself. Expired/revoked gh credentials still need native login.
- Signed activity cursors expire when their MCP server process restarts and must be used with the original filters. Concurrent changes to the visible window set `historyChanged`/`restartRequired`; a completed delivery is separate from source completeness. Checkpoint diagnostics identify matching approved sessions where possible; missing-message dates can still be unknown. Successful replay warnings clear after recovery. Dashboard source notices can be dismissed; acknowledgement persists for that workspace mode, source and diagnostic text. Changed diagnostic text shows a new notice. Dismissal does not remove the source details or alter MCP coverage.

- Windows x64 is the tested desktop target. macOS cleanup/packaging and Linux/WSL collector/MCP builds are implemented or portable in source but untested on those operating systems. Windows does not monitor WSL UNC mirrors.
- Claude/Codex persisted schemas can change. The researched versions and conservative final-response rules are documented in `docs/research-history-indexing.md`. Unavailable/deleted/private upstream history cannot be recovered; pending Claude text without a reliable final boundary is intentionally omitted. Delegated subagent transcripts are excluded.
- Retrieval uses local FTS with technical synonym expansion and a bounded spelling fallback over recent approved text. It is not an embedding/model search. Strict `all`/`phrase` modes remain available; approximate matches are evidence candidates, not proof. Rephrase with concrete identifiers if needed.
- Retained human text is bounded at 4 MiB per message, and source JSONL lines at 4 MiB. Larger human records produce an explicit collection gap; omitted tool records do not. Dashboard/MCP retrieval pages are independently bounded. Source references or actual rollback events that cannot be reconstructed remain visible coverage warnings. A partial JSONL tail waits for its completing newline.
- Claude Code 2.1.292 executed a bounded native skill verification: SubagentStart selected `mission-control:memory-reader`, which used ToolSearch and the read-only history search. Real multi-server recap quality is not established by that no-match test. Codex's native app-server performed actual tool discovery and a local MCP call without inference. Its CLI installed the plugin; explicit native MCP registration is required by the tested setup, rather than relying on bundled-server auto-activation.
- Official GitHub/Slack URLs, schemas, narrow read-tool configurations and host parsing were checked. Slack authentication remains owned by each host; its configuration is unchanged. The optional GitHub launcher uses the already-authorized local gh login without copying tokens into host configuration. Separately, the desktop PR overview's fixed GitHub CLI query was verified against the existing signed-in account. Workspace approval, subscriptions, token permissions and registered Slack OAuth client requirements still apply. An old Slack `xoxp` token is not a substitute for the official MCP OAuth flow.
- The compact PR overview requires GitHub CLI on PATH and uses its active github.com account. It shows authored open PRs across accessible repositories, up to six in the card and 20 fetched, with a total count and View all link. It is refreshed on opening Overview after its five-minute cache expires, or manually; it is not a live notification feed. Review states are supplied by GitHub, not inferred from chat. Enterprise hosts and multi-account aggregation are not implemented.
- A read-only plugin does not revoke unrelated permissions from the host. GitHub is also restricted at its official server; Slack's read subset is enforced through host tool allowlists/restricted Claude agent. Do not treat skill prose as a global sandbox.
- Existing projects need explicit approval after migration. Unapproved historical human text is excluded and approval revocation purges retained payload. Backups may contain old/excluded data and credentials/config references; history purge does not delete original transcripts. Upgrade helpers verify and retain two encrypted backups and remove obsolete unencrypted migration backups. A memory-server version in use is deferred until a later cleanup; active host connections are never killed.
- Resource figures depend on dataset, WebView2, hardware and visible/hidden state. The targets are approximately 150 MB background memory and <1% of one logical core; measured results are in `BENCHMARKS.md`.
- Version 0.4.3 replays existing sources with upgraded parser checkpoints while preserving user settings, repository groups and all project approvals. The real-data isolated replay recovered today's HelpDesk work in 7.62 seconds and drained the saved backlog in 64.39 seconds. Original transcripts and account credentials were unchanged by that replay. Installation checks are recorded separately in FINAL_INTEGRATION_CHECKLIST.md.

- An internal comparison on one real working day found a semantic regression despite reading all 233 retained messages. The final candidate scored 13 full / 9 partial / 2 missing against the old recap's 16 / 7 / 1 under the same 24-item rubric. It omitted two follow-up items; external-source discovery, concrete next actions and some readiness claims still need work. It used 3.69M tokens versus 10.20M, but did not meet the proposed 1M estimate or preserve all useful information. The evaluation report stays with local evaluation artifacts and is not part of the source package. Synthetic recall evidence and identical full/partitioned message fingerprints do not establish semantic completeness. No automatic ledger persistence or incremental weekly cache is implemented.
